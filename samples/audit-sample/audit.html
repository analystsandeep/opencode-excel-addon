1. Defined name points at a deleted range

broken_name

Name 'PriorYearTotal' refers to #REF!.

Why it matters
Any formula using this name is now pointing at nothing, and the failure can be masked by a cached value that still looks correct.

Suggested fix
Re-point 'PriorYearTotal' at the intended range or delete it, then search for its uses and correct them.

high

2. Circular reference (1 loop)

circular_reference

P&L!G33 P&L!H33 P&L!G33

Why it matters
A circular reference means the figure depends on itself. Excel resolves it iteratively, so the value drifts with every recalculation and is not reproducible from the inputs.

Suggested fix
Break the loop. Identify the cell that should be an input rather than a calculation, and replace one leg of the cycle with a typed assumption placed outside the loop.

high

3. Workbook depends on another file

external_links

References point outside this workbook. The files are Prior year P&L.xlsx.

Why it matters
External links break silently. The recipient sees stale cached values, and any figure that came from the other file is no longer verifiable from this one.

Suggested fix
Break the links. Paste the required values as labelled inputs on a source sheet, or rebuild the reference inside the workbook. Then check that no formula still contains a bracketed file name.

4. Tie-out fails for Total revenue equals the sum of every product line

tie_out

'P&L'!B9-SUM('P&L'!B5:B8) evaluates to -404.00 against a tolerance of 0.50, so it is out by 404.00.

Quantified impact 404.00 in the workbook's units.

Why it matters
Reconciliations exist because these two figures are supposed to agree. When they do not, at least one of them is wrong.

Suggested fix
Trace both sides to their inputs and correct the one that is incomplete. Re-run after the fix.

5. Typed value inside a calculated row

hardcoded_in_run, sheet P&L

Row 16 is calculated across B16:M16 but these cells hold typed numbers, starting with H16=12500. The pattern at B16 would give H16 = 492.55, so the typed value is off by +12,007.45.

Quantified impact 12,007.45 in the workbook's units.

Why it matters
A hardcoded number inside a calculated row is the most common way a model quietly stops tying. It survives every future update because nothing recalculates it.

Suggested fix
Replace each typed value with the formula its neighbours use, or move the assumption to an input sheet and reference it so the override is visible and labelled.

high

6. Cell shows a value but the formula resolves to an error

hidden_error, sheet P&L

1 cell(s) carry a stored number while the formula evaluates to an error. For example, P&L!B23 stores 1370 but ='Old workings v0'!B2 resolves to #REF!.

Why it matters
The reader sees a plausible number. The moment anyone recalculates, or links to the cell from another model, it becomes an error or a blank. This is the most dangerous class of defect in a workbook that is about to be circulated.

Suggested fix
Correct the formula at its source, then recompute and confirm the cell now shows the intended figure.

high

7. Stored result does not match the formula

stale_cache, sheet P&L

2 cell(s) hold a cached value that disagrees with a recomputation of the formula. For example, P&L!B12 shows 99999 but =B9-B11 evaluates to 2175.0 (difference -97,824.00).

Quantified impact 102,989.62 in the workbook's units.

Why it matters
The number on the page is not the number the formula produces. This happens when a file is written by a script or another tool, when a workbook is edited outside Excel, or when a calculation was interrupted. Every reader trusts the cached value, so the error travels silently.

Suggested fix
Recompute in Excel (F9), save, and re-run. If the recomputation changes a figure you have already reported, treat the cached value as wrong and trace what changed.

high

8. Total excludes the row or column next to its range

sum_coverage, sheet P&L

12 total cells in row 9 sum B5:B7 but the row directly outside the range (B8:M8) holds a value of 404 and is otherwise part of the same block. The totals affected are B9, C9, D9, E9, F9, G9 (+6 more). The excluded values sum to 5,640.00.

Quantified impact 5,640.00 in the workbook's units.

Why it matters
The classic broken model. A line is added after the total was built, the SUM range does not grow, and the figure is understated with no visible error. Nothing on the page looks wrong.

Suggested fix
Confirm the block is meant to include it, then extend each total along its own axis, from B5:B7 to B5:B8 (for example B9 changes from =SUM(B5:B7) to =SUM(B5:B8)), or delete the orphan row if it should not be there.

9. Hidden sheets carry content (1)

hidden_sheets

Not visible in the workbook tabs. They are Old workings.

Why it matters
A sheet the reader cannot see is a place where inputs, workings or stale calculations survive review. Reviewers routinely miss them.

Suggested fix
Unhide each sheet, decide whether it is load-bearing, and either label it as workings or delete it.

10. Same block displayed as both percent and decimal

format_mixing, sheet P&L

Row 21 holds 12 numbers, 11 formatted as percent and 1 as plain number. The ambiguous cells are I21. For example I21 displays as a plain 0.25.

Why it matters
A cell showing 0.07 and a cell showing 7% read as different magnitudes even when they hold the same number. In a margin or growth block that is how an order-of-magnitude error survives review.

Suggested fix
Apply one convention to the whole row, then re-check the dependent rows still foot after the change.

medium

11. Formula does not follow its row pattern

pattern_deviation, sheet P&L

J5 differs from the pattern used by 10 other cells on the same row 5. The pattern is =B5*1.03, as at C5. The deviation is J5 =I5+0.03.

Why it matters
Fill-across models rely on every cell in a period row being the same formula shifted. A deviation is either a deliberate exception that should be labelled or a copy-paste slip that will not survive the next roll-forward.

Suggested fix
Compare each listed formula with the pattern next to it and either restore the pattern or add a note explaining the exception.

12. Formulas have no stored results

no_cached_results

4 formula cells carry no cached value, e.g. P&L!B25, P&L!B27, P&L!G33, P&L!H33.

Why it matters
The workbook has not been recalculated since it was last written by a tool or script. Any figures another system reads from it may be blank or stale, and no formula audit alone can confirm the expected result.

Suggested fix
Open the workbook in Excel, let it calculate fully, save, and re-run this audit so the check can compare formula and result.

13. Hidden rows or columns inside the used range

hidden_rows_cols, sheet P&L

2 hidden row(s) (28, 29) and 0 hidden column(s).

Why it matters
Hidden rows and columns inside a data block are the standard way a period or entity is excluded from a total without anyone noticing.

Suggested fix
Unhide and review each one, or delete it. If a column is hidden only for presentation, move it out of the data block.

14. NOW() used 1 time

volatile_function, sheet P&L

NOW() appears in B27.

Why it matters
NOW is volatile and changes every time the file recalculates. In an audit trail that means the reported figure cannot be reproduced from the file alone.

Suggested fix
Replace with a fixed input or a non-volatile equivalent where possible, and document the assumption date where it cannot be avoided.
